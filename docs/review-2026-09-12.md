# Core safety review, 2026-09-12

An independent read-only review of the core found 23 issues; 13 were reproduced on
throwaway databases (sales.db, and a world.db driven by Jarvis's real commitments.py).
Every reproduced case is now a regression test in `tests/test_core_review_fixes.py`.

## Fixed

| # | Finding | Fix |
|---|---|---|
| 1 | A page on another localhost port could press Send with its own To/body (origin check compared host, not port) | Exact origin (scheme, host, port) must equal the server's own; Host header allowlist blocks DNS rebinding |
| 2 | "No, we will not sign…" supported "we will sign…" at explicit | Quotes must match in order; a negation the quote drops means not found; a loose match caps at medium; only an exact match may change a loop |
| 3 | Rejecting a loop linked by the model dropped a real Jarvis commitment | `loops.world_link` (mirror / adopted / imported); only our own mirrors are ever dropped; adopted/imported links are released, and closed only when the seller confirmed the loop done |
| 4 | Reopening a loop was undone at the next sync | Read-back recognises our own "in sales-coach" closures and reopens the Jarvis commitment instead |
| 5 | A timed-out send could go out twice; a failed row stayed sendable next to a redraft | Unknown-outcome errors keep the email 'sending' ("delivery unknown"); deterministic Message-ID; retry searches Sent first; "It was not sent" acknowledgement unlocks a retry; redraft retires failed rows and never drafts after a send |
| 6 | Jarvis skipped meetings the coach never processed (failed captures, internal domains) | Claims only calls that reached loops_reconciled without error, external domains only |
| 7 | Recommended actions and assumptions kept unearned confidence and reached emails | Assumptions cap at low, recommended at medium; recommended items need the seller's confirmation to feed an email |
| 8 | Owner check used the cited turn, not the one the quote matched | Channels come from the matched turns |
| 9 | A blank Jarvis counterparty matched every call | Empty counterparty matches nothing |
| 10 | Unconfirmed model links kept Jarvis items alive | Keep-alive and read-back act on confirmed loops only |
| 11 | Re-running a finished call dragged it back to review | Finished states are kept unless a new draft was actually created |
| 12 | A low claim could overwrite a value the seller cleared | Protection keys on the provenance, not on the value being non-empty |
| 13 | Bridge held the sales.db write lock during subprocess calls | Commits after every step; post-send bookkeeping retries on a lock |
| 14 | Claims were published only every 6 h | Published the moment loops reconcile |
| 15 | Only the literal [SLOTS] blocked sending | Any bracketed placeholder blocks |
| 16 | Unsupported summary items reached the drafter | Filtered before the email prompt |
| 17 | A broken plugin could break startup; removed plugin steps looked "finished" | register() failures are caught and recorded; unknown states raise |
| 18 | A user edit marked every competing proposal accepted | Only the matching one is accepted; the rest are rejected |
| 19 | Skip could mark a sent/sending email's call as skipped | email_done refuses while an email is 'sending' and records a sent email as sent |
| 20 | Failed events retried instantly | Backoff (attempts x 30 s); rate limits defer 15 min without spending an attempt |
| 21 | No Host check | Part of #1 |
| 23 | Loose name matching in bootstrap_import | Whole-name, exact-email or account-domain matches only |

## Accepted, not fixed
- 22: the Granola capture session still loads other claude.ai connectors while untrusted transcript text is in context. `-p` mode denies every tool not in `--allowedTools`, which is the protection relied on.
- Plugin handlers are re-run on retry of the event; handlers must be idempotent.

# Second review, 2026-09-12 (evening)

Five parallel read-only reviews of every subsystem (web, orchestrator/store, execution/automation,
live capture/coach, intel/agents/validators) found 37 issues; 33 were reproduced on throwaway
databases before anything was changed. All are fixed below; regression tests are in
`tests/test_review2_fixes.py`. The headline: no path sent mail without a click, but a buyer's reply
could close a Jarvis commitment on its own, and a Redraft racing a Send could mail a customer twice.

## Fixed

| Area | Finding | Fix |
|---|---|---|
| web | Redraft racing Send: v1 sent while v2 was drafted → both sendable, `gmail.sent == 2` | `step_email` re-checks after the agent returns and discards the new draft if an email went out or the call was closed; `run_pipeline` keeps a state the seller set (`email_sent`/`email_skipped`/`done`) instead of overwriting it; Send/Drafts buttons hidden while a rerun is queued; Send refused while a redraft is running |
| web | "Close without email" / "Mark sent" → 500 while an email is `sending` | Both redirect with the error, like Skip |
| web | "Close without email" left the draft sendable on a closed call | `email_done(sent=False)` rejects unsent drafts |
| web | Move to another deal left loops, email and claims on the old deal | They move with the call |
| web | Prep meeting time entered in IST displayed 5h30 late | Normalised as IST like the import form |
| web | Core `/emails/{id}/send|skip` accepted a nudge, acted, then 500 | Nudges are sent to their own page |
| web | `/clip?turns=<huge int>` → 500 | Turn numbers over 9 digits ignored |
| core | A failed handler's partial writes were committed with the failure record | `_settle_failure` and `claim_next` roll back first |
| core | An event whose handler crashed the process was re-claimed first on every start, forever | `recover_running` parks exhausted events; `claim_next` skips them |
| core | One `database is locked` outside the per-event try killed the worker thread silently | The loop survives, reconnects and logs |
| core | `embed.index_pending` held the write lock across Ollama HTTP calls | Commits before embedding |
| core | Pending `CALL_ENDED` left behind after a synchronous `salescoach process` | Retired when the pipeline finishes; `status` says when no worker is running |
| core | `deal add` without a name: traceback | Usage message, exit 2 |
| intel | Fuzzy match accepted a quote that *adds* a negation ("we will NOT sign" vs "we will sign") | A dropped negation token means not found (`negated`) |
| intel | Devanagari vowel signs stripped by `\w`; Hindi negations unknown | Category-based normalisation keeps marks; नहीं/नही/मत are negations |
| intel | Neighbour turn searched before the cited turn flipped the owner check | Cited turns first, neighbours only as fallback |
| intel | "I hope not." from the other speaker negated the next turn's commitment | Negation lookback stays on the matched turn |
| intel | Text on the THEM channel could become the seller's explicit commitment at medium | owner `me` + `explicit_commitment` off the seller's channel → low; transcript fenced and every prompt told it is data |
| intel | MEDDPICC `competition` and the competition risk shared one provenance row | Risk ids are `<deal>:risk:<type>`; old rows migrated on read |
| intel | Summary commitments (no quote check) reached the email drafter | Dropped from the email prompt; loops carry validated commitments |
| intel | Email prompt showed the last three edited emails from any deal | Filtered to the call's deal |
| intel | Same-named person at another account linked as a stakeholder | Name fallback limited to the deal's account |
| intel | Any buyer who shares the seller's first name was rejected as being the seller | Whole-name match |
| intel | LLM sandbox lived under `~/.claude`, an ancestor with a CLAUDE.md | `RUNTIME_DIR` defaults to `~/Library/Application Support/salescoach/runtime` |
| exec | A buyer's reply alone closed a bootstrap-imported Jarvis commitment | Imported loops carry `user_input` status provenance; a non-mirror link closes only when the seller set the status |
| exec | Errors before any HTTP call (a newline in the subject, a corrupt token file) left the row stuck in `sending` | `ValueError`/`TypeError` are "not sent"; a subject with a line break is refused before `sending` |
| exec | A stuck Save-to-Drafts attempt was searched for in Sent and blocked as a possible double send | `attempt_mode` recorded; Drafts searched; a stuck draft attempt is released and retried; the UI reports a recovered send as sent |
| exec | An exception at the 09:30 follow-up run skipped the whole day | Failed duties retry within 15 min |
| exec | A reply with no new text fell back to the quoted history, so our own sentences were analysed as the buyer's | Nothing new is nothing; such replies are marked analysed with no items |
| exec | `config.load` was cached for the process, so editing auto-send off needed a restart | Cache keyed on the file's mtime |
| live | Stop could orphan the capturing callcap child with the mic hot (SIGKILL is not forwarded; a pending mic prompt swallowed SIGTERM) | Capture runs in its own process group and is `killpg`'d on timeout; callcap installs its signal handlers on a control queue before the prompt and exits when its parent dies |
| live | `them` timestamps ratcheted to the worst delivery stall, offsetting every later sample against `me` | Tap timestamps anchored to the sample count, re-anchored only on a > 1 s dropout |
| live | Devanagari transcript text invisible to the fast cues and tokenizer | Unicode tokens, mark-preserving normalisation, Devanagari spellings in the cue lists |
| live | The seller describing their own company's process fired and showed `buying_process` | THEM channel only |
| live | "Hello ji" / "Namaste ji" became unexplored stakeholders | Longer `not_names`; an utterance-opening "X ji" is not a name |
| live | VAD noise floor stuck at its cap after loud audio followed by digital silence | Digital-zero blocks relax the floor toward its initial value |
| live | A nudge that failed to persist still spent the cooldown and budget | Not stored means not shown; the ranker takes it back |

## Accepted, not fixed
- The live Hindi tier still depends on which ASR model runs: Whisper in `hi` mode emits Devanagari (now
  covered), the Oriserve models emit Latin script (covered before). Both spellings are listed, but the
  cue lists are hand-written and will need tuning on real Hindi calls.
- `callcap` was rebuilt only in a scratch copy to prove it compiles; the installed binary is untouched
  because rebuilding voids the macOS permission grant. Rebuild with `callcap/build.sh` when convenient.
